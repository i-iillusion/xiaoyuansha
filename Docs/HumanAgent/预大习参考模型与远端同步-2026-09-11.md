## 3. HTML 明确展示的预大习模型

### 栈与结算行为

| 代码入口 | 模型实际行为 | 对游戏实现的意义 |
| --- | --- | --- |
| `init` / `stepDying` | 将进入死亡流程的人设为 alive=false，推入死亡结算；濒死阶段写死为“无人救援” | 这是演示中的可撤销死亡，不等于已完成游戏死亡；无人救援是场景简化，不能禁止正式救援 |
| `stepDeath` | 在亮身份牌前，若角色为 JR 则把其死亡帧暂停，压入新的预大习帧 | 发动时点具体化为死亡公开前；支持嵌套，不要递归调用当前不可逆的 `_handle_death` |
| 目标建立 | 触发时取 alive 的其他角色快照，排除发动者及其他处于死亡流程者 | 不对发动者再扣一次 2；暂停中的其他发动者同样不在此子规则的初始名单 |
| `stepYudaxi` | 每次只给一个目标扣 2；目标濒死就暂停父规则，压入其濒死/死亡流程 | 不是全员先同时扣完再统一处理；子规则处理完才恢复父规则的下一个目标 |
| `finishDeath` | 只有最终完成的死亡，才按 cause 帧增加一次 X | 归属按直接造成该死亡的那一次预大习；子规则的其他死亡不透传给父规则，被救回的不算 |
| 预大习结束 | X>0 时一次设置发动者 HP=X、累计摸 X、恢复 alive；X=0 不返回 | 回复是“至 X”而非“加 X”；不按每次死亡重复执行整套摸牌 |
| 死亡帧恢复 | 若该人恢复 alive，就撤销此死亡帧；否则完成死亡 | 死亡奖励、身份公开和单位清理不能因为临时 alive=false 就提前不可逆提交 |
| 目标继续 | 游标已前进；轮到目标时如果当前不存活则跳过 | 不回头重做已处理目标；模型只检查当前存活，不能误说“名单上曾死过就永远跳过” |

### 一个静态推演例子

采用 HTML 的“双 JR”预设：A=0（JR）、B=2（JR）、C=2（普通），列表顺序 A、B、C，A 初始触发。

1. A 的预大习扣 B 至 0，暂停 A；B 进入死亡公开前，触发自己的预大习。
2. B 的目标快照只有 C：A 与 B 此时都不在 alive 列表。B 扣 C 至 0，C 最终死亡，计入 B 的 X=1。
3. B 的规则结束，B 恢复至 1、摸 1，B 的死亡被撤销，不计入 A 的 X。
4. 返回 A，下一目标 C 已死亡，跳过。A 的 X=0，A 最终死亡。

因此模型末态为 B 存活且 HP=1，A/C 最终死亡。这是对代码的静态推演，不是本次运行日志，更不是已经接入游戏的判胜结果。

### 不可照搬的偏差与简化

- **座次起点偏差**：`targets=sim.roles.filter(...)` 按配置列表顺序，不按发动者下家旋转。例如 A/B/C/D 都在列表中而 C 发动，模型可能先处理 A，不是下家 D。正式规则沿用负责人明确的“从下家起”，不以该数组顺序覆盖文字裁定；本次没有修改用户 HTML。
- **生命状态不是同一语义**：游戏 `mark_dead()` 配合 `_handle_death` 会清牌、公开身份、奖惩、判胜；HTML 的 alive=false 仍可撤销。建议增加“等待死亡规则结算完成”的中间状态/事务，或用独立上下文表示，最终提交后才触发召唤物消失。具体实现方案不等同于新增规则。
- **没有完整救援**：演示没有桃/酒、装傻、贤者、身份转换、召唤物与伤害后技能，不能因演示缺失就删除这些窗口。其与预大习衔接时仍要核对现有裁定。
- **没有游戏判胜**：演示结束、重复检测、预设选项都不定义身份胜负或全灭结果。现在已获授权的仅是结算超限兜底平局，不自动推广到普通全灭。
- **循环检测省略历史量**：`recordState` 的键不含 draws/deaths 累计值。正式游戏手牌可影响救援，不能只照搬这个状态键认定真正循环；“循环搜索种子”按钮也不代表已经证明存在无限循环。
- **5000 步是保护阈值**：负责人允许设置阈值后视为平局。建议以超过 5000 次规则结算状态推进作为可配置初值；输入等待、UI 帧和网络时间不计数。该数值不是负责人钦定常量，未来可调整；不得声称已核验未提供的循环不可能性证明。
- **12 人配置上限只是演示界面**：HTML 允许最多 12 个配置项，不覆盖本次明确的正式游戏 10 人玩家上限。

## 4. 真正剩余的问题

1. **轮次**：一号位/末位死亡、整回合跳过与“跳过不算经过”怎样影响轮末；新单位正常加入已定，但轮末位置变化怎样记轮仍需案例。
2. **山/火龙及单位计数**：山遮挡与两侧等人数、火龙产蛋的第二个回合口径；召唤物参与距离/拼点/技能人数；消失是否触发“单位死亡”效果及计入预大习 X。最终死亡后消失的时间点不再悬置。
3. **预大习组合**：正式救援、弃牌/身份公开/击杀奖惩、奸雄声明和身份判胜之间的最终提交顺序；目标快照与动态单位的适配。核心嵌套、直接 X、一次回复摸牌和超限平局已不再是空白。
4. **乱斗补充**：最低人数、全员最终死亡但没有超限时的结果、身份相关技能与击杀奖励、验收方式。上限 10 和最后存活者胜不再重复询问。
5. **安迪后续材料**：无人机初始手牌、不同位置多个地雷/无来源等复杂效果，首版可不受这些缺口阻塞。中心放雷、基本邻接约定、同位不叠加与单线拦截均已定。

所有未决项都可以答“我也不清楚，需要与其他人商议”；不因未决组合而重新悬置已明确的主体规则。
