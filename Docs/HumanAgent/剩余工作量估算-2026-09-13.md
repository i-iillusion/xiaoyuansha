# 剩余工作量与额度估算

本估算用于排期，不是额度保证，也不是已消耗 token 的计量。起点为 A2a 完成后的项目：本地规则原型已有七将、两类基础模式、求救/预大习核心和牌区基础，但 AI、装备实例、扩展身份、动态轮次/空间及多数武将仍未齐备。

## 估算口径

以近期 A1/A2a 这种包含实现、回归、CI 修正和文档的小批次为一个工作单位。以下是主观工程区间，已留有组合回归和返工余量；不是用户已批准缩小首版范围。

| 累计目标 | 剩余同等批次估计 |
| --- | --- |
| 已有七将的可玩核心：选牌、装备、基础 AI、终局/重开闭环 | 20～35 |
| 尽量覆盖手册武将的首版：另含里奥等扩将、2～10 人布局、经典/奸雄、轮次、火龙和山 | 80～160 |

暂不包含美术、无人机/地雷、联网、作弊系统，也不计等待他人裁定/试玩的时间；这些等待不能由 token 预算解决。全首版工作不是仅仅将剩余武将逐个写入选将表。

## 五小时额度不能直接按 token 常数换算

[官方说明](https://learn.chatgpt.com/docs/pricing)指出，模型、任务复杂度、上下文、推理、工具与缓存都会影响额度；五小时消息数量只是估计，另可能有周限额。官方未在此给出适用于当前账号的固定 token/五小时兑换数。这里也没有账号用量百分比与完整输入/缓存/输出 token 账单，不能把工具输出字数当实际 token 消耗。

实际可用的校准公式：若相同模型下一个同等批次平均用掉五小时额度的 p%，则剩余额度单位约为「批次数 × p / 100」。这是消耗量，不是保证经过对应数量的五小时就完成，也不免除周限额。

| 假设每批实际消耗 | 可玩核心 | 尽量完整首版（累计） |
| --- | --- | --- |
| 10% | 2～3.5 个额度 | 8～16 个额度 |
| 20% | 4～7 个额度 | 16～32 个额度 |
| 30% | 6～10.5 个额度 | 24～48 个额度 |

这些百分比只是敏感性分析，不是读取到的账号数据。提供最近两三批的模型、开始/结束额度（避开重置时刻和其他并发使用）后可缩小区间。若另有每批实际 token 账单 T，累计 token 才可按「批次数 × T」估算；输入、缓存输入和输出应分别统计，不混成额度等价物。
