## 2. 五人标准身份局基线（ST-04）

范围仅为现有的五人标准原型：一主公、一忠臣、两反贼、一内奸；座位可随机。不是对 QA-008 首版范围的代答，也不开放新模式。

基础依据采用[三国杀官方新手教程的四身份获胜条件](https://www.sanguosha.com/news/20140415_1948_1720)，核对日期 2026-09-08；本项目手册 5.1.2 对反贼与唯一内奸的区分也有相同表述，但其中奸雄转换部分不适用于本批。

- 主公尚未死亡，且所有反贼、内奸均已死亡：主公与忠臣阵营胜。
- 主公已死亡，唯一未死亡角色为内奸：内奸胜。
- 主公已死亡，其余普通已完成死亡结算的局面：反贼阵营胜；不要求反贼仍在场，也不取决于谁造成了伤害。
- 负体力、濒死和已死亡必须区分。存在未完成的濒死救援时暂不宣告胜方；该窗口结束后重新检查。2026-09-12 最终裁定要求实际死亡后先公开身份、再清牌；预大习在求救后、死亡前，成功保留手牌/装备/判定区。死亡入口已按[首批修复](QA.md#qa-t07实际死亡清牌时身份尚未公开)调整顺序；完整预大习未接入，不能因此记为全部验收。
- 1V1（ST-06）、奸雄声明、身份复原（QA-006）、预大习及特殊多人死亡的整体时序（QA-007）不在本批范围。非法身份配置不套用五人算法；同时全员死亡等未决特殊局面不由程序猜定胜方。

### 验收矩阵

“死亡”均指 `Player.is_dead()`，不是只把 hp 设为 0。除明确写有濒死者外，各案例的救援窗口均已结束。

| 编号 | 局面 / 操作 | 预期 |
| --- | --- | --- |
| V01 | 五人均存活 | 不结束 |
| V02 | 两反贼死亡，内奸仍存活，主公存活 | 不结束 |
| V03 | 两反贼死亡，内奸濒死（包括负体力） | 不结束；不能提前判主公胜 |
| V04 | 两反贼和内奸死亡，主公存活；忠臣存活或已死亡 | 主公阵营胜 |
| V05 | 主公死亡，其余四人存活；分别传入反贼、忠臣、内奸、null 作为击杀者 | 均为反贼胜 |
| V06 | 只剩主公和内奸；主公死亡，来源为内奸或 null | 内奸胜 |
| V07 | 反贼全部死亡，但忠臣与内奸均存活时主公死亡 | 反贼胜（已死亡阵营也可获胜） |
| V08 | 主公进入濒死，或负体力尚可连续用桃自救 | 救援未结束不判胜；救回后继续对局 |
| V09 | 主公已确认死亡，另有濒死者尚在救援 | 暂不判胜；最后一个救援窗口结束后重查，不遗漏获胜通知 |
| V10 | 主公不在座位 0，使用同样的死亡组合 | 胜方不变 |
| V11 | 对同一死亡事件 / 已结束局面重复检查 | 奖惩、game_over 信号和终局弹窗不重复 |
| V12 | 已死亡角色被直接赋正体力，但未显式恢复死亡状态 | 仍视为已死亡，不误算为存活 |
| V13 | 两人无身份局、含奸雄、缺失/重复主公、非标准五人配比 | 五人判胜器不处理，不补造对应模式规则 |
| V14 | 所有角色同时被外部特殊效果标死 | 本批不裁定；不能据此宣称 QA-007 已完成 |

V09 只规定普通救援期间不提前结束及恢复后需重查，不规定预大习的多人处理顺序。正常单次伤害的 before_death checkpoint 仍先于死亡确认，不能被判胜器替代。

## 3. 死亡状态审计边界

本批只处理 ST-15 中与终局和死亡入口直接相关的调用，不宣称完成全部调用审计。

| 调用区域 | 所需语义 | 处理方向 |
| --- | --- | --- |
| _check_win_condition 的主公/反贼/内奸名单 | 是否已确认死亡；是否仍有救援窗口 | 使用 is_dead / is_dying，不使用 is_alive 推断阵亡 |
| _handle_death 的进入条件 | 濒死处理结束且仍处于 DYING | 显式检查 is_dying，保留重复处理保护 |
| _check_dying 的装傻、贤者入口 | 仍处于 DYING 才尝试救援 | 不把 DEAD 当作仍可救援；救回后重新检查被延后的普通终局 |
| 烈火盾、是啊的失血后死亡入口 | 只有仍 DYING 才进入死亡管线 | 统一使用显式状态检查；不改变费用数值和可选性 |
| 可选出牌、目标选择、行动后技能 | 多数调用要求 ACTIVE | 不机械全局替换 is_alive；后续分别核查目标和参与者规则 |
| 轮次、召唤物、装傻参与人数和特殊多人事件 | 存在未决规则或更大调用范围 | 留给对应 QA / ST，不顺带推断 |
