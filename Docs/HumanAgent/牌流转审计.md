# 牌流转审计：第一批

日期：2026-09-08。起点 `2dfe9e7`，对应 ST-08/10 的局部审计与修复，为 ST-09 提供实施入口。不是全手册覆盖表（ST-02），也不代表完整牌生命周期已通过验收。规则依据为手册第 4 章和 QA-102：任意牌使用/打出后固定为具体牌，任何转移不能重新声明类型。

## 现有数据与入口

| 环节 | 实际表示 / 入口 | 审计结论 |
| --- | --- | --- |
| 摸牌 | _draw_blank_cards 将 null 放入 Player.hand | 未具体化手牌没有卡牌类型，不应在转移时随机生成类型 |
| 具体手牌 | Player.hand 也可存 CardBase；判定区同样存资源 | 有 card_id、sub_type、source_seat；转移应保留原资源，不重新 create |
| 另设具体牌区 | determined_cards；顺手装备/判定与勾镰爪写入 | hand_size、has_any_card 与旧费用逻辑不统一包含此区；需要统一手牌语义，不能仅接一个点击回调 |
| 装备区 | equipment 保存槽位到 CardSubType，而非 CardBase | 当前无法保留原装备实例 ID；后续需迁移为实体/状态记录，兼容四马、暗置与装备唯一性 |
| 主动使用 / 响应 | play_card、execute_card_on_target、_consume_trick 及闪/AOE/无懈等分支 | 多处直接 pop_back 再 create 声明牌。混合手牌可能消耗错误具体牌，取消/费用/目标需共用入口 |
| 手牌拆偷 | _steal_hand | 旧版先 pop_back 后给获得者 null，丢失具体化状态；拆桥未写弃牌堆。本批修复 |
| 装备拆偷 | _steal_equip | 旧版拆桥不记弃牌；本批补记具体装备，暗置占位不造实体。不重定义失去装备触发或贤者标记归属 |
| 判定区拆偷 | _steal_judgment | 顺手已保留资源，但拆桥漏记；本批将原资源放入弃牌堆 |
| 异步拆偷 | _play_steal_card 分派手牌/判定时未 await | 本批补 await，确保失牌替代结束后再同步/返回，并复查牌区是否仍有对象 |
| 弃牌阶段 / 技能费用 | _do_discard、装逼、摄魂刀、Gay、没用等有直接移除手牌路径 | 仍需区分弃牌效果、发动费用、使用牌；不要全局替换成烈火盾可代付的入口 |
| 死亡 / 复原 | _discard_all_cards、_do_sage_save | 具体手牌/判定/另设具体牌区会进弃牌堆，装备按类型重建，null 与暗置占位不造实体。本批沿用此表示约定 |
| 转移与唯一性 | EquipmentPool 的 claim 一旦占用即保留 | 具体装备再装备不能直接重复 claim；也不能通过释放占用使别人重新声明同名装备。留 ST-09/11 联合处理 |

## 本批变更与边界

1. 顺手拿走普通手牌时，移动原 CardBase/null；保持卡牌类型、ID 和来源元数据，不公开输出对方手牌名。
2. 拆桥弃具体手牌或判定牌时，原资源进入弃牌堆一次。未具体化 null 手牌只扣数量，沿用死亡弃牌约定，不凭空指定一种具体牌。
3. 拆桥弃装备时，按现有装备区数据结构重建同类型弃牌资源；不宣称已解决装备实例身份。暗置占位仅清理槽位，不生成假装备牌。
4. 拆偷效果等待烈火盾选择结束；等待后牌区已清空或目标已死亡时，不再生成或转移新牌。费用与替代效果仍采用原规则，不修改 QA-114 的技能费用限制。

保留原有的手牌取末尾/判定取末尾选择方式，不额外制定随机抽取规则；装备替换争议（QA-001）和暗置抢占（QA-104）不在本批内。已具体化牌的完整再使用、统一手牌数量和发动费用仍未实现，不能将本批称作 QA-102 全部完成。

## 下一批建议

- 先建立单一手牌视图，明确 null 与具体实例的选择/移除接口，保留现有判定和装备信息。
- 主动使用、响应、技能弃牌分别走不同接口；确认合法目标和费用后才提交，不把具体牌重新声明为另一类型。
- 再接入 _on_determined_card_clicked，与普通牌共用次数/距离/响应流程；装备再使用与唯一性迁移同时处理。
- 按函数族补齐弃牌阶段、死亡、技能费用和转移的记账；未澄清的装备/特殊时机继续隔离。

## 第二批：按类型支付与延时牌去向

日期：2026-09-08，起点 `f739d30`，对应 ST-09 的物理支付基础和 ST-10 的局部去向修正。第一批的快照表保留为历史证据，以下为新增实现。

[HandPayment](../../Scripts/HandPayment.gd) 只处理 `Player.hand` 内的物理牌选择与原子移除：

- `find_index` 只预查，不修改手牌；自动选择时优先同类型具体牌，再选择 null 任意牌。这是默认选牌策略，不是增加游戏规则。
- `take` 返回原具体资源，或在实际支付时把一个 null 具体化；没有匹配牌则返回 null，牌区不变。
- 可传入明确选中的资源；类型错误或已离手时拒绝，不悄悄改扣其他牌。此参数供后续界面接入，本批没有开放独立具体牌点击入口。
- 该接口不是弃牌费用接口：技能要求弃任意手牌时，不能拿它强制要求某一种牌。

| 接入路径 | 本批行为 | 未涵盖部分 |
| --- | --- | --- |
| _consume_trick | 即时锦囊只消耗同类型牌/任意牌，原物理资源入弃牌堆；失败返回 false，调用者不继续结算 | 出牌前提示/全部目标合法性仍由原调用者负责 |
| _take_trick_card | 取得本次锦囊资源但不决定去向；是啊独立支付失血，失败不给资源 | 保留原有技能视为使用约定，不实现通用虚拟牌系统 |
| 四种延时锦囊 | 乐不思蜀、兵粮寸断、火烧连营、闪电将原资源放入判定区；放置时不再同时入弃牌堆，重新使用时更新放置者来源 | 判定失效后转移、火烧生成蔓延副本等仍需独立审计 |
| 出牌阶段桃、酒 | 先匹配并支付，再回复/增加酒层数；原资源进弃牌堆 | 濒死响应、杀/闪、其他响应入口还未统一迁移 |

明确未完成：determined_cards 与 hand 的统一计数、装备实例/唯一性、杀与各类响应的支付、技能费用、_on_determined_card_clicked、完整选择/取消交互。因此不能将 ST-09 或 QA-102 记为全部完成；旧响应路径仍有把具体牌当任意牌使用的缺口。

验证：Godot 4.7.2 导入及 HandPayment、GameManager、test_hand_payment、test_confirmed_rules 四份脚本的仅解析检查通过。新增 [test_hand_payment.gd](../../Test/test_hand_payment.gd)，覆盖错误类型、显式选择失效、实例保留、基本牌支付失败与是啊费用；尚未手动执行，未直接加入 CI。

现有 CI 脚本 test_confirmed_rules 增加 3 条断言：火烧保留原实例、放置时不进弃牌堆、判定后原资源只弃一次。推送时由现有工作流自动执行；其结果只覆盖该脚本实际断言，不替代新增完整用例。测试/诊断脚本总数由 32 增至 33。

## 第三批：主动杀与杀的出闪响应

日期：2026-09-09，起点 `7a17459`，继续 ST-09 的局部迁移。

- 单目标主动杀、火杀、雷杀按声明的具体类型支付；原资源进入弃牌堆。支付发生在使用次数、酒效果和青龙摸牌之前，费用不足时不产生这些副作用。进入选择目标前先预查，确认时再支付。
- 多目标杀只支付一张原牌并记录一次使用；空目标列表不收费用。不改变原有逐目标效果处理，也未重写全部目标合法性入口。
- 杀的出闪响应先检查实际闪/任意牌，答应后再次匹配支付，原闪进入弃牌堆后才触发八卦摸牌；放弃或费用不足不会扣别种牌。
- 神速等“视为使用杀”的内部效果入口仍与物理出牌费用分离，没有给它们额外收一张手牌。

本批不将“主动声明普通杀”与“响应要求杀”混为一谈；决斗、AOE 的杀响应另批处理，不在这里推断/修改其类型匹配。无懈、舍己、濒死响应、装备、技能弃牌及完整具体牌点击入口仍未统一。ST-09/QA-102 仍是部分实现。

回归材料：test_hand_payment 补充费用不足保留次数/酒/青龙、原杀实例、多目标一次支付和普通杀不能主动改称火杀；该独立脚本未手动运行。现有 CI 的 test_rule_settlement 增加 5 条断言，检查错误类型不能出闪、实际闪入弃牌堆及八卦后摸牌；原代受用例改用真实的舍己与闪，不再用两张具体杀冒充。旧断言继续保留，CI 脚本数量不变。

提交前 Godot 4.7.2 导入及 GameManager、test_hand_payment、test_rule_settlement 三份脚本的仅解析检查通过，无脚本错误。没有手动执行测试；新增主动杀支付用例不在现有 CI 脚本选择范围内，不能因核心回归通过而记作全部验证。

## 第四批：无懈与舍己响应支付

日期：2026-09-09，起点 `eb7f7c9`，继续 ST-09/10。依据手册 4.2、QA-102 和既有代受裁定；不调整无懈轮询顺序、代受时机或 AI 策略。

- 两种响应的可用牌预查、技能选择中的物理支付选项和最终扣牌均按对应类型/任意牌判断，不再把任意具体手牌当作可用响应。
- 成功支付将原 CardBase 放入弃牌堆一次；任意牌只在支付时具体化。放弃、匹配失败不扣其他类型的牌。
- 弹窗返回后复查角色可行动/下跪状态，实际扣牌时再次匹配，避免过期选择继续生效。
- 【是～啊～】仍走独立失血费用：没有匹配牌但有其他具体手牌时，也可选择技能代付；不消耗这些牌、不生成实体弃牌。原有失血失败处理不变。

回归材料加入现有 CI 的 test_rule_settlement：两种响应各 13 条断言（共 26 条），覆盖错误类型、原实例、任意牌、放弃、弹窗期间失牌/下跪、技能代付/取消/拒绝技能后用牌。原有代受后出闪的集成用例保留。本地仅完成 Godot 4.7.2 导入和脚本解析，无脚本错误；没有手动运行测试，推送后由既有 CI 执行。
