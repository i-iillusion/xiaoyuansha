## 已审计的真实入口

1. `GameManager._register_unit_body` / `_retire_final_unit`：登记仅创建成员/Node，最终死亡通知仅接已 DEAD 对象；都不执行真实技能召唤、求救和父效果续接。正常死亡和 `SUMMONER_LOST` 必须分派，异步技能后效不能只发信号后立刻继续。
2. `RoundLedger`：固定整数号、玩家空间顺序、本轮名额/额外栈；`TurnManager` 阶段信号、普通/赠送/额外状态帧及次数仍是整数 actor。**不能 append 火龙到 GameManager.players，也不能让 seat=-1 索引最后一个玩家。** 新有回合单位需要独立稳定行动节点，固定玩家轮首与身份号不变。
3. `GameManager._on_phase_changed` / `_do_start_pending` / `_do_draw` / `_run_judgment`：当前 `players[pid]` 和 `players.has(p)` 为玩家入口；单位必须接真正 body 和成员资格，不借主人 pid 偷跑。单位自己的回合重置/摸1/弃牌上限要实际验收。
4. `get_trick_targets` / `_get_strike_targets` / `ordinary_seat_distance` / `Player.attack_distance_to`：当前候选玩家，距离还有双方坐骑/劣马修正。Q1 未答不能把“继承距离”静默解释为其中一层。山分区留 I04，不用本次顺带重构山。
5. `HandPayment`：保留原手中实体、响应/任意牌具体化；不用于无类型的弃3手牌费用。新费用还须沿真实弃牌与觉醒/失效续接，不用复制手牌支付。
6. `CardActionEvent`：当前 `actor_seat` / `turn_owner_seat`；`GameManager._history_event` 的公开 actor/targets 也只记固定座号。单位 USE 必须有独立主体/ID，不用 controller seat冒充；预习标记仍只按真实使用者资格结算，不送给主人。
7. `_resolve_dying` / `_check_dying` / `_run_rescue_round`：当前仅玩家成员、玩家回合索引。真实单位伤害/求救需要成员与轮询起点对接；预大习名单仍只玩家。不要用 `_retire_final_unit` 跳过真实求救。
8. `_handle_death`：身份奖惩按实际 killer，尚无召唤击杀映射，Q2 待答。身份局不能因单位 ID 混入身份候选影响主公死亡/奸雄声明；乱斗仍以玩家胜负为准。
9. `PlayerObservation` / `UnitObservation` / `LanGameBridge` / `LanSession` / `LanRoom`：协议8 players/space/turn是固定玩家，units只读。未来需独立 acting-unit 与单位空间/目标令牌，白名单和私牌权限一起改；不得把字符串 unitID塞进原 turn 数组下标。旧令牌必须随实际单位/成员/状态变动过期。
