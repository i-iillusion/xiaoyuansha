# DEV-F02a：锦囊替换规则与入口映射

2026-10-06。来源：现行手册4.2、6.7，CARD-01、TIME-01/02/04、TURN-03。仅完成原文/生产入口审计及未替换的真实用牌基线；未实现替换，不把候选新版或现有代码当新裁决。

## 已明确边界

- 预习在一张除无懈、舍己外的非延时锦囊被使用时提供可选替换，费用一个预习标记。原触发牌为下表九种；基本牌、装备、四种延时锦囊、无懈、舍己不能作为触发原牌。
- 替换后所选目标数不得小于原来所选目标数，不是要求目标必须相同。是否重选及谁选待F02-Q2；不能把人数条件代替新牌其他合法性。
- “原牌排除无懈/舍己”不自动证明新牌也以相同列表排除。原文新牌写“另一张非延时性锦囊”；两张响应锦囊的目标是效果/伤害，正常主动替换例没有对应使用窗口，不制造可用候选。若未来确有合法跨类型窗口，须先给具体局面裁决，不宣称本表是新牌全集。
- CARD-01保留具体牌实例，但技能明确更换是否永久改名未答，见Q3。不能先改CardBase.sub_type再拿原资源引用冒充身份已解决。
- 无懈/舍己虽不触发替换，里奥本人回合用真实手牌使用它们仍按6.7获得标记，不因替换排除项取消其用牌计数。

## 工程缺口：不得据此自动补规则

1. TARGET_TRICKS混有三种延时牌，GLOBAL_TRICKS只含五种群体即时牌；不能拿任一常量直接作替换白名单。get_trick_targets仅做角色合法目标枚举，不提供群体集合/目标数快照。
2. _consume_trick返回bool，内部_take_trick_card获取原实体，物理牌入弃后_record_card_action。虚拟是啊只付体力、不制造物理弃牌。后续效果函数不接收已支付资源/统一用牌上下文；替换需要保留原实体及独立效果类型，不能再次调用新牌支付函数而扣第二张。
3. 使用事实同步给预习，然后调用者才登记锦囊次数、处理效果。新增标记可否当场用于本牌、计数归属分别待Q1/Q4；现有顺序不是裁决。未来不能重复发布USE冒充一次替换、虚构第二张实体。
4. 群体函数逐项遍历存活者；桃园/五谷满体力判定、卸甲空装备判定位于无懈后。现有遍历次数不等于原文目标数，也不能以“实际产生回血/摸牌/伤害的人数”作为所选目标数。正式目标快照和无效/不能成为目标区别见Q5；原文桃园/五谷只针对受伤者已明确，不再请负责人重复裁决。
5. 顺/拆在支付前已选旧目标牌区，替换后旧牌区选择不能带入新目标或新牌效果；保留原牌支付、旧选区的取消与过期边界。新效果不得递归调用完整主动出牌函数造成再支付、次数检查或新USE。
6. 无懈现在按每名效果目标逐次询问；“牌被使用时替换”需在原效果开始之前接窗口，而非做到首名目标后中途改变剩余效果。连续替换次数/虚拟原牌资格见Q6a/b。新窗口继续遵守独立答复、原人物/牌资源/阶段/重开代次复核，取消、失效、无合法候选分别处理；未授权新超时默认。

## 验收层级与下一步

新增prep_trick_baseline_cases挂载原核心七组入口：九种原牌×任意/具体双区经真实共同AI行动→结束阶段；每张只一USE、一原实体入弃、一预习。无懈/舍己真实物理使用在本人/他人回合分别计1/0，并入弃一次。此为替换前基线，不是任何替换组合已实现的证明。

Q1～Q6详见待裁决具体案例。规则答复只解对应分支；未答不影响本批审计/原入口基线。后续DEV-F02b先回写答复、选择已明确的同目标数子集，逐次提交真实支付→替换窗口→新效果→无懈/响应及取消/失效测试；目标集合/数量的原文差异须先修，不能套群体现有循环长度。F03开放里奥及G/H/I仍后续；不推送、不合main。
