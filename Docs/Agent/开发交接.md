## 代码入口

- [MainMenu.gd](../../Scripts/MainMenu.gd)：菜单、测试模式和武将选择。
- [GameManager.gd](../../Scripts/GameManager.gd)：对局、技能结算和交互主控。
- [IdentityVictory.gd](../../Scripts/IdentityVictory.gd)：只读五人标准判胜；不处理 1V1、奸雄及未决特殊时序。
- [HandPayment.gd](../../Scripts/HandPayment.gd)：物理手牌按类型选择/移除；已接入锦囊、出牌阶段桃/酒/杀、杀的出闪、无懈/舍己及决斗/AOE 响应。响应杀接受普通/火/雷杀，主动声明仍严格匹配；不是技能弃牌费用接口。接入范围见[牌流转审计](../HumanAgent/牌流转审计.md)，青龙响应计数缺口见 QA-T06。
- [TurnManager.gd](../../Scripts/TurnManager.gd)：回合阶段与使用次数；另按座位记录每回合首次使用/打出杀，供青龙触发，不与主动杀次数混用。见 QA-T06。
- `GameManager._rescue_options` / `_use_rescue_card` / `_run_rescue_round`：基础自救与他人求救共用合法性、支付及顺序；`_use_dying_card` 为兼容包装。玩家0用独立救援弹窗，AI 自救并按公开阵营选择救人；详见 QA-T09 与牌流转审计第八批。
- [Player.gd](../../Scripts/Player.gd)：角色状态、死亡状态和开局快照。
- [DyingContext.gd](../../Scripts/DyingContext.gd) / `GameManager._resolve_dying`：统一普通伤害、丈八、烈火盾、是啊的濒死窗口；`before_death` 现在传 DyingContext，原链通过 `effect_chain` 访问。记录独立濒死者与原因，防同窗口重入；所有活跃窗口返回后才允许判胜。基础求救已接入，不是完整预大习或所有救援技能实现。
- [EffectChain.gd](../../Scripts/EffectChain.gd)、[DamageRecord.gd](../../Scripts/DamageRecord.gd)、[RuleScheduler.gd](../../Scripts/RuleScheduler.gd)：伤害链、伤害记录和结算边界调度。

## 实现边界

当前为本地规则原型，入口开放 1V1 和五人测试模式。完整 AI、全部手册武将和部分复杂系统尚未完成。2026-09-08 已修正五人胜负条件及部分死亡状态入口，尚未执行专项回归用例，不能记为已验收；2026-09-11 两人无身份乱斗基础规则已定，但尚未接入当前 1V1 入口。证据见[规则差异与五人局验收](../HumanAgent/规则差异与五人局验收.md)、QA-T05；待确认裁定、范围及专项审计以 QA 为准。

`is_alive()` 当前表示可行动，判断已死亡使用 `is_dead()`，判断救援窗口使用 `is_dying()`。新增武将状态时须检查开局快照的登记，保持贤者复原兼容。

新增伤害/流失路径应 await `_resolve_dying`，不能复制 `_check_dying` 后直接 `_handle_death` 的旧组合。`_check_dying` 依次执行全体普通求救、装傻、贤者；已救回不再开放死亡前窗口。普通求救沿当前回合的既有轮转顺序，放弃后不重问；不可擅自将此顺序替代预大习的下家起算。重复进入同一活跃窗口直接返回，不是等待原窗口完成的接口；不得把这个返回当作“已救回/已死亡”。窗口状态不属于武将牌，不加入贤者快照。

AI 的公开阵营策略是可调整的出牌意愿，不是“只有队友能救援”的合法性限制；人类可救任何合法目标。旧战斗用例通过 `_rescue_choice_override` 显式设全员拒绝，以固定原场景；新 `Test/rescue_cases.gd` 由核心脚本调用，覆盖实际 AI、支付、轮询与弹窗。旧玩家0自救钩子仍优先于通用测试决策。

测试和诊断脚本集中在 `Test/`。未收到用户明确要求时，不手动运行测试；推送与 PR 会按现有工作流自动触发 CI。命令和 CI 范围见[项目 README](../../README.md)。
