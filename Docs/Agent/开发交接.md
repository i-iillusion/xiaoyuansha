## 代码导航与硬边界

| 文件/入口 | 职责与约束 |
| --- | --- |
| GameManager.gd | 主对局与交互；约七千行，按入口小步改，不整文件重构 |
| Player.gd | 双手牌区计数、装备类型/实例兼容、角色与开局快照；is_alive表示可行动，is_dead/is_dying分别判断最终死亡和濒死 |
| HandPayment / HandSelection / HandDiscardPrompt | 分别是用/打出支付、选牌快照、UI；用牌与技能弃牌不可混用 |
| EquipmentPool.gd | 目前只按牌名claim；重装备实体与新造同名需要分开 |
| DyingContext / _resolve_dying | 伤害、流失的统一求救/死亡前窗口；重复活跃窗口返回不表示已经完成 |
| YudaxiResolver.gd | 独立嵌套帧、直接死亡X、成功保三牌区、超限平局；里奥其他技能未齐 |
| EffectChain / DamageRecord / RuleScheduler | 普通伤害链、数据与高优先级边界；不代表新版所有事件都已实现 |
| TurnManager.gd | 当前阶段/回合计数；完整动态轮次与空间仍待I |
| IdentityVictory / FreeForAllVictory | 现有五人身份与基础乱斗判胜；奸雄/完整连环终局不是已完成 |
| GeneralData / MainMenu | 七将加稻草人数据；不能登记名字就假装全技能实现 |
| Test/ 与 .github/workflows/ci.yml | 七组自动验收；新case须挂载，helper测试不替代真实入口 |

预大习顺序：普通求救及既定保命选择→实际死亡前预大习→成功保手牌/装备/判定区、不翻身份；失败最终死亡→翻身份→清牌。不得先清再还，不先移除控制者召唤物。

费用按发起者和原因分；通常手牌为任意牌，具体牌保留原实例；装备不得重复归属。await之后复查动作有效性，强制选牌不能以取消规避；AI只观察有权获取的信息。
