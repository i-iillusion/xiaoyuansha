## 代码入口

- [MainMenu.gd](../../Scripts/MainMenu.gd)：菜单、测试模式和武将选择。
- [GameManager.gd](../../Scripts/GameManager.gd)：对局、技能结算和交互主控。
- [IdentityVictory.gd](../../Scripts/IdentityVictory.gd)：只读五人标准判胜；不处理 1V1、奸雄及未决特殊时序。
- [HandPayment.gd](../../Scripts/HandPayment.gd)：物理手牌按类型选择/移除；已接入锦囊、出牌阶段桃/酒/杀、杀的出闪、无懈/舍己及决斗/AOE 响应。响应杀接受普通/火/雷杀，主动声明仍严格匹配；不是技能弃牌费用接口。接入范围见[牌流转审计](../HumanAgent/牌流转审计.md)，青龙响应计数缺口见 QA-T06。
- [TurnManager.gd](../../Scripts/TurnManager.gd)：回合阶段与使用次数；另按座位记录每回合首次使用/打出杀，供青龙触发，不与主动杀次数混用。见 QA-T06。
- `GameManager._use_dying_card`：濒死桃/酒自救按钮与测试共用的物理支付入口，接入 HandPayment；不含他人/AI 救援。见牌流转审计第七批。
- [Player.gd](../../Scripts/Player.gd)：角色状态、死亡状态和开局快照。
- [EffectChain.gd](../../Scripts/EffectChain.gd)、[DamageRecord.gd](../../Scripts/DamageRecord.gd)、[RuleScheduler.gd](../../Scripts/RuleScheduler.gd)：伤害链、伤害记录和结算边界调度。

## 实现边界

当前为本地规则原型，入口开放 1V1 和五人测试模式。完整 AI、全部手册武将和部分复杂系统尚未完成。2026-09-08 已修正五人胜负条件及部分死亡状态入口，尚未执行回归用例，不能记为已验收；1V1 仍待裁定。证据见[规则差异与五人局验收](../HumanAgent/规则差异与五人局验收.md)、QA-T05；待确认裁定、范围及专项审计以 QA 为准。

`is_alive()` 当前表示可行动，判断已死亡使用 `is_dead()`，判断救援窗口使用 `is_dying()`。新增武将状态时须检查开局快照的登记，保持贤者复原兼容。

测试和诊断脚本集中在 `Test/`。未收到用户明确要求时，不手动运行测试；推送与 PR 会按现有工作流自动触发 CI。命令和 CI 范围见[项目 README](../../README.md)。

持续维护的代码导航与交接说明放在本目录。临时日志、个人记忆及凭据不应提交；规则疑问和用户答复放入 `HumanAgent/`，不要在内部说明中代填裁定。
